## 1. Problem Definition & Project Background

### 1.1 Background
Climate change represents one of the most critical challenges facing the modern world. Anthropogenic greenhouse gas emissions, widespread industrialization, deforestation, and changing land use patterns have destabilized historical meteorological baselines. As a consequence, localized weather extremes—including severe heatwaves, catastrophic flash floods, prolonged droughts, and elevated carbon dioxide concentrations—occur with unprecedented frequency.

The **EarthScape Climate Agency** is mandated to observe, analyze, and mitigate the repercussions of climate volatility across diverse geographic regions. The agency routinely ingests high-frequency data streams generated by:
1. Ground-level automatic weather sensor stations (monitoring temperature, precipitation, ambient humidity, barometric pressure).
2. Remote sensing environmental satellites.
3. Urban air quality and greenhouse gas monitors (tracking CO2 parts-per-million).

### 1.2 Problem Definition
Managing and deriving actionable insights from these data feeds introduces major technological challenges:
- **Massive Data Volumes & Velocity:** Traditional relational databases fail to scale efficiently when processing multi-year telemetry from thousands of sensor nodes.
- **Pattern & Outlier Identification:** Extreme weather occurrences are often buried within millions of normal readings, necessitating robust big data batch algorithms (MapReduce) combined with unsupervised machine learning anomaly detectors.
- **Predictive Horizon Forecasting:** Environmental decision-makers require accurate multi-month trend forecasts equipped with statistical confidence intervals to allocate disaster preparedness resources.
- **Unified Stakeholder Experience:** Environmental scientists, field analysts, and government administrators require distinct, role-secured interactive visualization dashboards to make informed decisions.

## 3. System Architecture & Design Specifications

### 3.1 Tiered Architectural Model
EarthScape is structured into four decoupled layers:
1. **Client Tier (Presentation):** Built with React 18, Vite, and Tailwind CSS. Employs Leaflet.js for interactive GIS weather station mapping and Recharts for climate trend curves.
2. **Application & Gateway Tier:** Built on Node.js and Express.js. Implements JSON Web Token (JWT) session security, Role-Based Access Control (RBAC), multipart file streaming with Fast-CSV, and real-time Server-Sent Events (SSE).
3. **Big Data Processing & Storage Tier:** Utilizes Apache Hadoop Distributed File System (HDFS) for raw dataset archiving, Python MapReduce streaming jobs for distributed batch aggregations, and Apache Impala for SQL warehouse analysis.
4. **Machine Learning Microservice:** Autonomous Python FastAPI service running Scikit-Learn algorithms (Polynomial Ridge Regression, Isolation Forest, IQR, Pearson/Spearman correlation matrices).

### 3.2 Security, Reliability & Compliance (Non-Functional Requirements)
- **Data Security:** All authentication endpoints enforce salted password hashing via `bcryptjs` (10 rounds). Protected API routes validate signed Bearer JWT tokens.
- **High Availability & 99% Uptime:** The backend includes an automated fallback to an In-Memory MongoDB engine if external MongoDB is down, and algorithmic JS fallbacks if the Python ML microservice is restarting.
- **Scalability:** The REST architecture is stateless, allowing seamless containerization (Docker) and horizontal scaling across clusters.
- **Disaster Recovery & Backup:** Ingested datasets are archived simultaneously in HDFS (`/earthscape/raw/`) and local storage, with processed analytics exported to standard CSV formats for cold backups.

## 6. Test Data Used in the Project

The platform includes two comprehensive test datasets in `data/sample/`:

1. **`normal_data.csv` (2,920 Records):**
   - Spans 8 distinct geographic weather stations: **Karachi, Lahore, Islamabad, Quetta, Peshawar, Multan, Gilgit, Gwadar**.
   - Contains daily observations spanning multiple seasons:
     - `date`: YYYY-MM-DD
     - `location`, `latitude`, `longitude`
     - `temperature` (°C), `humidity` (%), `rainfall` (mm)
     - `wind_speed` (km/h), `air_pressure` (hPa), `co2` (ppm)
     - `source`: National Weather Station Network

2. **`anomaly_data.csv` (2,920 Records):**
   - Injected with extreme climatic outliers for machine learning benchmark validation:
     - Heatwave spikes ($>48^\circ\text{C}$)
     - Monsoon torrential rainfall events ($>140\text{ mm}$)
     - Industrial carbon plumes ($>475\text{ ppm}$)
     - Severe tropical depressurization ($<975\text{ hPa}$)

## 7. Assumptions & Limitations

1. **Storage Mode Flexibility:** The system supports both live Apache HDFS and high-performance local disk storage mode. In development environments where a multi-node Hadoop cluster is not configured, the application operates seamlessly using its internal HDFS emulation service.
2. **Database Engine Resilience:** For ease of evaluation and zero-configuration setups, the backend includes an automated MongoMemoryServer fallback so evaluators do not need an active MongoDB service running locally.
3. **ML Microservice Decoupling:** The Node.js server maintains native algorithmic fallbacks (ordinary least squares regression and Z-score calculations) ensuring the frontend remains operational even if the Python process is temporarily restarted.
4. **Map Tile Network Requirement:** The Leaflet GIS map requires an internet connection to pull live OpenStreetMap raster tiles; all numerical charts, MapReduce jobs, and data tables function completely offline.
